# ZJU 宿舍跨校区千兆 IPv6 隧道方案 (zju-dorm-ipv6-tunnel)

一套面向高校宿舍网（有线网口仅分配校内 IPv4、无原生 IPv6，而实验室/工位网口具备原生 CERNET2 千兆 IPv6）的**跨校区/跨楼宇千兆 IPv6 隧道与单 L2TP 账号双向共享方案**。

本仓库已针对 AI 编程助手（Codex / Claude Code / Cursor）做了全自动部署适配，并提供完整的硬件选型与避坑指南。

---

把本仓库克隆到本地，直接复制下面这段话发送给你的 **Codex / Claude Code / Cursor**：

> ```text
> 请阅读当前仓库中的 AGENTS.md，帮我完成宿舍路由器与工位节点的跨校区 IPv6 隧道一键部署与连通性测试。先探测我的本地网络环境，再向我询问缺失的 SSH 密码和 IP 参数。

AI 助手会自动探测你的网关、生成 `.env` 配置、打通双端免密 SSH、写入防掉线自愈守护服务，并在部署完成后自动跑一遍 CERNET2 镜像站实测带宽验收。

## 二、为什么需要这套方案？常见方案的三大性能瓶颈

在校园网环境中，宿舍与工位之间在 `10.98.0.0/16` 校内内网层是千兆直连互通的（RTT 仅 `1.2 ~ 1.8 ms`），但普通自建 GRE 隧道往往只能跑到 `50 ~ 270 Mbps`，核心卡在以下三个瓶颈：

```mermaid

    subgraph Bad1["误区 1：未配置 10.98.0.0/16 静态路由 (~60 Mbps)"]
        A1["工位节点回程 GRE 报文"] -->|"命中 default dev l2tp-vpn"| A2["被塞进学校 L2TP VPN 二次封装
(IPv6->GRE->PPP->L2TP->UDP->IPv4)
MTU 被压低至 1436，绕行学校 LNS 限速"]
    end

    subgraph Bad2["误区 2：工位使用百元双核 ARM 硬路由 (~273 Mbps)"]
        B1["工位路由器 (如 AX3000E 双核 Cortex-A7)"] -->|"Linux ip_gre + ip6table_nat (NAT66)"| B2["高通 NSS 硬件加速引擎失效
每秒 2.4 万包全部落入双核 1GHz CPU 软中断
单臂一进一出合计处理 ~550 Mbps 即触发 100% CPU 满载"]
    end

    subgraph Good["本仓库推荐方案：工位百元 x86 小主机 + 宿舍硬路由 (840+ Mbps)"]

开启 64KB GRO/GSO 超帧合并 + raw 表 GRE NOTRACK + 四核 RPS"] -->|"校内千兆 IPv4 直连 (MTU 1476)
零 L2TP 占用"| C2["宿舍四核硬路由 (仅负责解封装，命中 SFE 快径)
实测隧道吞吐 840 Mbps，公网下载 ~500 Mbps"]
    end
```

### 三个阶段的真实演进实测数据

| 阶段与方案 | 跨校区 GRE 隧道带宽 (`iperf3`) | 宿舍单线程公网 IPv6 下载 | 宿舍 4 并发公网 IPv6 下载 | 满载时工位设备 CPU 状态 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 初始双路由状态** (回程误入 `l2tp-vpn`) | `~69 Mbps` (`8.6 MB/s`) | `7.11 MB/s` (`56.9 Mbps`) | `8.61 MB/s` (`68.9 Mbps`) | 双核 ARM `sirq 75%+` |
| **2. 双路由优化后** (旁路 L2TP + 对齐 MTU 1476 + RPS) | `~273 Mbps` (`34.15 MB/s`) | `21.70 MB/s` (`173.6 Mbps`) | `34.15 MB/s` (`273.2 Mbps`) | **双核 ARM `96.9%`（算力见顶）** |
| **3. 工位换用 N3700 x86 小主机** (本仓库推荐方案) | **`840 Mbps` (`105.0 MB/s`)** | **`42.09 MB/s` (`336.7 Mbps`)** | **`61.72 MB/s` (`493.8 Mbps`)** | **四核 x86 仅占 `~70%`（全程满睿频 2.4GHz）** |

## 三、单 L2TP 账号双向互补架构（工位零 L2TP 占用）

如果校园网账号只允许 **1 台设备**同时拨 L2TP（或者不想影响宿舍路由器的正常外网体验），本仓库默认启用**单 L2TP 双向互补模式（`ENABLE_OFFICE_L2TP="0"`）**：

```mermaid
flowchart LR
    subgraph Office["工位节点 (无需拨 L2TP)"]
        O_Node["工位 Linux 小主机
隧道 IPv4: 10.255.255.1/30
隧道 IPv6: fd00:cafe::1/64"]
        O_V6["工位原生 CERNET2 IPv6 出口
(交换机直接下发，不依赖 L2TP)"]
    end

    subgraph Dorm["宿舍路由器 (独占唯一 L2TP 账号)"]
        D_Router["宿舍 OpenWrt / 小米路由器
隧道 IPv4: 10.255.255.2/30
隧道 IPv6: fd00:cafe::2/64"]
        D_V4["宿舍 L2TP 公网 IPv4 出口"]
        D_LAN["宿舍全部终端 (电脑 / NAS / 手机)"]
    end

    D_LAN --> D_Router
    D_Router -- "① 宿舍公网 IPv6 走 GRE 隧道由工位出网 (840 Mbps)" --> O_Node --> O_V6
    O_Node -- "② 工位本机校外 IPv4 走 GRE 隧道借道宿舍出网
(校内 10.0.0.0/8 保持工位网口直连)" --> D_Router --> D_V4
```

- **宿舍体验零影响**：唯一的 L2TP 账号由宿舍路由器 100% 独占，宿舍 IPv4 外网完全保持原样；同时宿舍所有设备自动获得接近千兆的原生教育网 IPv6。
- **工位节点同样具备双栈外网**：工位小主机的校内流量（`10.0.0.0/8`）直接走工位物理网口，原生 IPv6 直接走工位交换机出口，而校外纯 IPv4 流量自动通过 GRE 隧道借道宿舍路由器的 L2TP 出网。

## 四、硬件推荐与选购避坑指南

### 1. 工位节点硬件档位推荐

| 档位 | 推荐设备型号 | 二手参考价 | 实测 IPv6 隧道极限 | 适用人群与点评 |
| :--- | :--- | :--- | :--- | :--- |
| **零成本档** | 闲置小米路由器（AX3000E / AX3000T / CR880x，开启 SSH） | **¥0（利用旧路由）** | **~270 Mbps** (`~34 MB/s`) | 适合已有闲置路由器、对 30 MB/s 下载速度满意的同学，直接用 `scripts/deploy-office-openwrt.sh` 部署。 |
| **甜点性价比档（强烈推荐）** | **Intel NUC5PGYH / NUC5CPYH (N3700 / N3050)** 或 J1900 / J4125 迷你小主机 (4G+32G eMMC) | **¥100 ~ ¥180** | **840+ Mbps** (`~105 MB/s` 跑满千兆) | 功耗仅 5~10W，体积巴掌大，自带千兆网口 + Intel 无线网卡（可做应急管理热点），跑满千兆有线网口物理上限。 |
| **高配进阶档** | Intel N100 迷你主机 / 软路由 | **¥350 ~ ¥500** | **1000+ Mbps** | 适合后续还想在工位跑 Docker 或其他计算任务的同学；仅做 IPv6 隧道转发选百元 N3700 即已完全溢出。 |

### 2. 电源适配器选购避坑（极其重要！）

如果在闲鱼购买不带原装电源的 Intel NUC（如 `NUC5PGYH` / `NUC5CPYH`）或迷你主机，配电源时**务必核对以下两点**：

1. **严禁拿路由器的 12V 电源线凑合插在 19V 的 NUC 上！**
   - 虽然 12V 欠压不会烧坏主板，且在空载待机（4~5W）时看似能亮机，但一旦开始跑满千兆 IPv6 下载，CPU 四核睿频 + 网卡满负荷收发会使整机功耗升至 15W+。
   - 在 12V 下所需电流是 19V 的 **1.58 倍**，普通 12V 1A/1.5A 电源会瞬间过流导致电压跌落，触发主板 **UVLO（欠压闭锁保护）直接断电关机**。
   - **正确规格**：请购买 **19V 3.42A（65W）** 笔记本/迷你主机电源（京东/淘宝约 ¥35~¥48）。
2. **插头尺寸必须选 `5.5 * 2.5mm`（切勿买成 `4.0 * 1.35mm`）！**
   - 许多第三方“华硕便携 65W 19V 3.42A”电源链接有多个插头规格选项：
     - ❌ **`4.0 * 1.35mm`**：华硕超极本专用细头，插进 NUC 会松动无法通电；
     - ✅ **`5.5 * 2.5mm`**：Intel NUC 标准 DC 接口尺寸（外径 5.5mm、内径 2.5mm），下单时务必看清规格框再付款。

## 五、工位无显示器“盲插网线开机”防失联设计

工位通常没有多余的显示器和键盘，`scripts/deploy-office-linux.sh` 内置了四重防失联保障：

1. **宿舍待机 / 工位自动激活双模式**：在宿舍插网线（`192.168.*`）预配置时自动处于 `dorm-standby` 待机模式，不干扰现有网络；带去工位插上校园网（`10.98.*`）通电 15 秒内自动切换为 `office-active` 模式拉起隧道。
2. **无限次 DHCP 重试 + 克隆 MAC 自动继承**：修复了 `NetworkManager` 默认重试 4 次失败后放弃连接的问题（无论先开机还是先插网线都能自动连上），支持克隆工位原设备 MAC 直接继承原 IP。
3. **校内网主动推送 IP（免域名保底）**：工位小主机拿到 `10.98.x.x` IP 的瞬间，直接通过校内网 SSH 将自己的最新 IP 写入宿舍路由器的 `/tmp/office_nuc_ip` 并自动切换隧道对端。
4. **`NUC-Rescue` 本地无线应急热点（100% 物理保底）**：利用小主机自带的无线网卡自动广播 `NUC-Rescue` 热点（默认网关 `192.168.99.1`）。哪怕工位墙口彻底断网或网线没插好，带笔记本去工位连上该 Wi-Fi 执行 `ssh root@192.168.99.1` 即可直接登录排障。
